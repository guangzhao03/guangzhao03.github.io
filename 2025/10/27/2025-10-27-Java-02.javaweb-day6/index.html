JDBC:(Java DataBase Connectivity),就是使用Java语言操作关系型数据库的一套API。

常用：JDBC、MyBatis、MyBatisPlus

JDBC

  • JDBC(Java DataBase Connectivity)，就是使用Java语言操作关系型数据库的一套API。

  • 本质：

    • sun公司官方定义的一套操作所有关系型数据库的规范，即接口。
    • 各个数据库厂商去实现这些接口，提供数据库驱动jar包
    • 我们可以使用这套接口编程，真正执行的代码是驱动jar包中的实现类。

  • ResultSet（结果集对象）：ResultSet rs=statement.executeQuery()

    • next():将光标从当前位置向前移动一行，并判断当前行为是否为有效行，返回值为boolean
      • true：有效行，当前行有数据
      • false：无效行：当前行无数据
    • getXxx(…)获取数据，可以根据列的编号获取，也可以根据列名获取（推荐）。

预编译sql

在SQL语句中用？占位符。

1、静态sql（参数硬编码）

2、预编译sql（参数动态传递）

预编译sql 安全、性能更高。

SQL注入：通过控制输入来修改事先定义好的SQL语句，以达到执行代码对服务器进行攻击的方法。

  • 优势二：性能更高

数据库连接池

  • 数据库连接池是个容器，负责分配、管理数据库连接（Connection）

  • 它允许应用程序重复使用一个现有的数据库连接，而不是再重新建立一个。

  • 释放空闲事件超过最大空闲时间的连接，来避免因为没有释放连接而引起的数据库连接遗漏。

  • 优势

    • 1、资源重用
    • 2、提升系统响应速度
    • 3、避免数据库连接遗漏

  • 标准接口：DataSource

    • 官方（sun）提供的数据库连接池接口，由第三方组织实现此接口。
    • 功能：获取连接 getConnection()

符号 说明 场景 优缺点

为什么使用@Param注解

1、默认行为与参数名称丢失：在 Java 编译后，方法的参数名称默认不会保留在字节码中（除非使用 -parameters编译参数）。因此，当 MyBatis 遇到多个参数时，它无法通过反射直接获取到参数原本的名称（如 username, password），只能为它们生成默认的别名，如 param1, param2… 或 arg0, arg1… 。如果你在 XML 中试图使用 #{username}，MyBatis 会找不到这个名称的参数从而报错。

2、@Param注解的作用：@Param注解的作用就是显式地告诉 MyBatis 每个参数应该被叫什么名字。当你使用了 @Param("username")，MyBatis 就会将这个参数放入一个 Map 中，其键（key）为 “username”，这样在 XML 中就可以通过 #{username}找到它了

3、Spring Boot 的编译配置：值得注意的是，Spring Boot 2.x 版本在其父工程中默认配置了 -parameters编译参数，这使得编译器会在字节码中保留方法参数的名称

。在这种情况下，即使不加 @Param注解，有时在多参数情况下也能通过形参名成功引用。

XML映射配置

  • 在MyBatis中，既可以通过注解配置SQL语句，也可以通过XML配置文件配置SQL语句，XML文件放在resoureces里面。
  • 默认规则：
    • 1、XML映射文件的名称和Mapper接口名称一致，并且将XML映射文件和Mapper接口放置在相同包下（同包同名）
    • 2、XML映射文件的namespace属性为Mapper接口全限定名一致
    • 3、XML映射中的sql语句的id和Mapper接口中的方法名一致，并且保持返回类型一致。

resources里面是目录，目录里要用斜杠/不用.

  • 在MyBatis的开发中，到底使用注解开发还是XML开发？

​ 使用Mybatis的注解，主要是完成一些简单的增删改查功能。如果需要实现复杂的SQL功能，建议使用XML来配置映射文件。
