Java网络编程

  • 可以让设备中的程序与网络中其他设备的程序进行数据交互的技术。

基本的通信架构

  • 基本的通信架构主要有两种形式，CS架构（Client客户端/Server服务端）、BS架构（Browser浏览器/Server服务端）

CS架构：客户端需要程序员开发，用户需要下载客户端

BS架构：不需要程序员开发客户端，需要用户下载浏览器

网络编程三要素：IP、端口、协议

IP：设备在网络中的唯一标识

端口：应用程序在设备中的唯一标识

协议：连接和数据在网络中传播的规则

  • InetAddress

代表IP地址

UDP通信

  • 特点：无连接、不可靠
  • 不事先建立连接；发送端每次要把发送的数据、接收端IP、等信息封装成一个数据包，发出去就不管了
  • Java提供了一java.net.DatagramSocket类来实现UDP通信

一发一收

客户端实现流程

  1. 创建DatagramSocket对象 发送的人
  2. 创建DatagramPacket 发送的东西 指定ip和端口
  3. 调用DatagramSocket对象的send方法发送
  4. 释放资源

服务端

  1. 创建DatagramSocket对象 接受的人
  2. 创建DatagramPacket 发送的东西
  3. 调用DatagramSocket对象的receive方法接受
  4. 释放资源

多发多收

  • 接收端只负责收数据包，无所谓哪个发送端的数据包

TCP通信

  • 特点：面向连接、可靠
  • 通信双方事先会采用“三次握手”方式建立连接，实现端到端通信，底层能保证数据成功给服务端
  • Java提供了一个实现类java.net.Socket类来实现TCP通信

TCP喜欢用DataOutputStream

一发一收

客户端：

  1. 创建客户端Socket对象，请求与服务器连接
  2. 使用socket对象调用getOutputStream方法得到字节输出流
  3. 使用字节输出流完成数据的发送
  4. 释放资源

服务端：

  • 服务端是通过java.net包下的ServerSocket类实现的。
  1. 创建ServerSocket对象，注册服务端端口
  2. 调用ServerSocket对象的accept()方法，等待客户端连接，并得到Socket管道对象
  3. 通过Socket调用getInputStream()方法得到字节输入流、完成数据的接受
  4. 释放资源。

多发多收

客户端注意每次发送完flush一下输出流 确保发送成功

调用flush()会强制将缓冲区中的数据立即写入底层输出流（即Socket的输出流），并清空缓冲区。这意味着数据会被推送至操作系统的网络协议栈，但实际到达服务器的时间仍受网络延迟影响

若不调用flush()，缓冲区未满时数据会一直驻留内存。例如发送小数据包（如心跳包、控制指令），可能长时间无法触发自动发送，导致服务器收不到实时消息

在即时通信、游戏指令、金融交易等场景，需要确保数据立刻发出而非等待缓冲区填满。手动调用flush()可降低通信延迟
