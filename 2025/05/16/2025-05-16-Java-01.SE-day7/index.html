final

final关键字是最终的意思，可以修饰类、方法、变量

  • 修饰类：该类被称为最终类，特点是不能被继承了
  • 修饰方法：该方法被称为最终方法，特点是不能被重写
  • 修饰变量：该变量有且仅能被赋值一次

public final class A{}

什么时候用？一般不用，工具类不能被继承

public final void show(){}

抽象类后场景解释

final double rate=3.14

保护数据，防止二次修改

一般把final放到static的后面

final修饰基本类型/引用类型的变量

static final 修饰的变量是常量

程序编译后，常量会被宏替换

单例类（软件设计模式）

什么是设计模式？

一个问题通常有n种解法，最优秀的解法被称为设计模式。

设计模式有二十多种

关于设计模式，学什么？

1、解决什么问题

2、怎么写

单例设计模式

  • 作用：确保某个类只创建一个对象

饿汉式单例

拿之前就创建好了

写法：

  • 把类的构造器私有
  • 定义一个变量记住类的对象
  • 定义一个类方法，返回对象。

懒汉式单例

拿的时候再创建。

写法：

  • 构造器私有
  • 定义一个静态变量存储对象
  • 提供一个静态方法，保证返回的是同一个对象

枚举类

  • 枚举类是一种特殊类
  • 枚举类中的第一行，只能写枚举类的对象名称，且要用逗号隔开。
  • 这些名称，本质是常量，每个常量都记住了枚举类的一个对象。

枚举类都是最终类不能被继承。枚举类继承了java.lang.Enum类

枚举类的第一行只能罗列一些名称，这些名称都是常量，并且每个常量会记住枚举类的一个对象。

枚举类的构造器都是私有的，因此，枚举类对外不能创建对象。

枚举类的常见应用场景

  • 枚举类适合做信息的分类和标志

抽象类

abstract 可以修饰类和成员方法

注意事项

  • 抽象类中不一定有抽象方法，有抽象方法的类必须是抽象类。
  • 类的成员：成员变量、方法、构造器、抽象类都可以有。
  • 抽象类最主要的特点：抽象类不能创建对象，仅仅作为一种特殊的父类，让子类继承并实现。
  • 一个类继承抽象类，必须重写完抽象类的全部抽象方法，否则这个类也必须定义为抽象类。

抽象类的好处

  • 父类知道每个子类都要做某个行为，但每个子类要做的事情不一样，父类就定义为抽象方法，交给子类去重写实现

设计抽象类，更好的支持多态。

抽象类不能创建对象，可以指向子类对象。

模板方法设计模式

  • 提供了一个方法作为完成某类功能的模板，模板方法封装了每个实现步骤，但允许子类提供特定步骤的实现。
  • 模板方法设计模式可以：提高代码复用性，并简化子类设计。

接口

  • java提供了一个关键字interface定义出接口

传统接口里面只能写常量

jdk8之前接口中只能定义常量和抽象方法

常量一定要初始化值

抽象方法不能有方法体，只能声明。

  • 接口不能创建对象

  • 接口被类实现 implements

接口好处

  • 弥补单继承的不足，一个类可以实现多个接口，使类的角色更多，功能更强大。
  • 让程序可以面向接口编程，这样程序员就可以灵活方便的切各种业务实现（更利于程序的解耦合）。

JDK8接口新增三个方法

  • 增加了接口能力，更便于项目的扩展和维护

接口的注意事项

  1. 接口和接口可以多继承，一个接口可以继承多个接口（重点）
  2. 一个接口继承多个接口，如果多个接口中存在方法签名冲突，则此时不支持多继承，也不支持多实现。

签名冲突 类似接口A,B A: string show（）; B:void show(); C implements A,B{} 出现冲突。

  1. 一个类继承了父类，同时又实现了接口，如果父类和接口有同名的默认方法，实现类会优先使用父类的。

  2. 一个类实现了多个接口，如果多个接口中存在同名的默认方法，可以不冲突，这个类重写该方法即可。

对于3： 接口名.super.方法() 调用接口的方法 默认调用父类的方法

对于4：接口各有两个同名的fault方法

接口和抽象类的区别

相同点

  1. 都是抽象形式，都可以有抽象方法，都不能创建对象。
  2. 都是派生子类形式，抽象类是被子类继承使用，接口是被实现类实现。
  3. 继承抽象类或者实现接口，都必须重写他们的抽象方法，否则自己成为抽象类。
  4. 都能支持多态

不同点

  1. 抽象类中可以定义类的全部不同成员，接口只能定义常量，抽象方法，JDK8新增三种方法
  2. 抽象类只能被类单继承，接口可以被类多实现。
  3. 一个类继承抽象类就不能再继承其他类，一个类实现了接口（还可以继承其他类或者实现其他接口）
  4. 抽象类体现模板思想更利于做父类实现代码的复用性。
  5. 接口更适合做功能的解耦合。集合都是功能
