claude两个记忆机制

(1) 轮次结束钩子（Turn Stop Hook）

  • 每次与用户的交互结束后，系统会自动 fork 一个独立的后台 Agent
  • 这个 Agent 会复用当前会话的 KV Cache，完整回顾整个交互过程
  • 自动判断哪些信息值得保存，并更新到对应的 Markdown 文件中
  • 所有记忆文件都有结构化的描述，不会一开始就加载全文，节省上下文 token

(2) Auto-dream（”做梦” 机制）

  • 大约每隔一天，如果该项目的会话数量超过 5 个，系统会自动启动一个更深层的记忆整理进程
  • 这个后台 Agent 会重放最近所有的会话记录，进行 “信息榨干”
  • 具体工作包括：纠正错误的记忆、合并重复的信息、提炼核心要点、将零散的笔记整理成结构化的文档
  • 这个过程非常像人类睡觉时的做梦机制，通过重放经历来巩固记忆、整合知识
