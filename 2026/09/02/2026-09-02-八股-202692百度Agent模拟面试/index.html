# 2026-09-02 百度 Agent 日常实习 模拟面试复盘 > 模拟范围:百度一面(技术面)风格。题池依据牛客/CSDN 公开面经:百度 Agent 岗特色 = RAG 问得深 + 大模型训练基础(RLHF/DPO/LoRA)会考。 > 结构:Agent 基础 → RAG → 大模型基础 → 工程与评估 → 开放设计(项目部分跳过,简历未完成) --- ## Q2 Agent vs Workflow ✅ **题目**:Agent 和 Workflow 的区别?判断标准? **我的答案**:控制权一个给 AI 一个给程序员;能固定流程就用 workflow,否则 agent。 **点评**:核心对(即 Anthropic《Building effective agents》原话)。两处要修: - 表达排序要先想好:"workflow 适合流程固定场景,agent 适合灵活/开放式场景" - **缺成本维度**:agent 循环调 LLM = 延迟高、token 贵、不可预测;Anthropic 建议"从最简单方案开始,必要时才加复杂度" **必背**:workflow 五模式 —— prompt chaining / routing / parallelization / orchestrator-workers / evaluator-optimizer。 --- ## Q3 Function Calling 原理 ✅ **题目**:实现原理?模型会执行函数吗?全流程? **我的答案**:带 name+description 的 JSON 声明工具;模型不执行只输出调用意图;客户端解析执行后回传,模型再加工。 **点评**:最关键点(模型不执行,执行方在客户端)答对了。修正: - 工具定义还有 **input_schema**(JSON Schema 约束参数),不只是 name+description - 流程按编号说:① tools 参数带上定义 → ② 模型返回工具名+参数(stop_reason="tool_use")→ ③ 客户端解析、校验、执行 → ④ 结果作为 tool_result 回传(带 tool_call_id)→ ⑤ 循环直到模型不再调工具 - 加分:并行工具调用、权限控制(危险操作需确认) **Q3-追问:工具名不存在/参数不合 schema 怎么办?** ✅ 答对:错误信息作为 tool_result 返还模型自我纠正。补: - **设重试上限**(如同一工具连败 3 次即终止/降级),否则就是死循环 - 错误信息要**可操作**("missing required field `city`" 而非堆栈) --- ## Q4 RAG 完整流程 ✅ **题目**:Offline / Online 两阶段分别做什么? **我的答案**:离线:切 chunk → 向量化 → 入库;在线:query 向量化 → 相似度取 top-k → chunk+query 送模型生成。 **点评**:流程完整。提升: - **chunking 策略**:固定长度+overlap、按语义/标题切;权衡:太小上下文不全,太大稀释检索精度 - 词汇:"余弦值判断" → "向量相似度(余弦/内积)取 top-k";报得出 Milvus/FAISS,百度自家叫 BES - 离线在向量化前还有**清洗预处理**;查询端有 **query 预处理**(改写/扩展) --- ## Q4-追问 多路召回与重排 ⚠️(概念混,重点复习) **题目**:召不回"退换货政策"怎么办?多路召回是什么?为什么要 rerank? **我的答案**:HyDE 改写问题;多路=不同策略多召回;粗召回分别 encode,重排一起 encode。 **点评**:直觉好但概念错位 —— 1. **HyDE ≠ query 改写**。三个概念分开: - **Query 改写/扩展**:同义词、口语转书面、拆多意图 - **HyDE**:让 LLM 生成**假设性答案文档**,拿假答案的向量去检索(答案-答案向量空间更近) - **多路召回**:多通道并行检索再合并 2. **多路召回要能举例**:向量召回(语义)+ BM25/关键词(专有名词、型号、错误码)+ 标签过滤;互补,合并用 RRF 3. **重排核心对比(本题考点,必背)**: - **bi-encoder(双塔)**:query 和 doc **各自独立**编码 → 快 → 粗召回 - **cross-encoder**:query 和 doc **拼一起**送模型出相关性分 → 精但慢 → 只排 top 几十 - 我答的 "bioencode" 是错的,正确是 bi-encoder / cross-encoder - 常用:bge-reranker、Cohere rerank、百度自家重排 **记忆锚点**:bi = 各编码各的 = 快 = 粗;cross = 一起编码 = 精但慢 = 精排。 --- ## Q5 Pretraining / SFT / RLHF ✅ **题目**:三阶段各干什么?loss 和 target?为什么 SFT 之后还要 RLHF? **我的答案**:预训练学知识;SFT 纠正知识/学会 QA 格式;RLHF 学人类喜欢的说法;loss 衡量差距;SFT 学格式,RLHF 让人听得懂。 **点评**:定性方向全对。精确化: - **Pretraining**:海量无标注文本上做 next token prediction,loss = 交叉熵,target = 下一个 token(面经原题,要能具体说出) - **SFT 不是纠错,是教格式和行为**:高质量 (instruction, response) 对,只对 response 算 loss - **RLHF 完整版**:先训奖励模型 RM(人类排序),再用 PPO/DPO/GRPO 优化 - **为什么还要 RLHF(我没答的部分)**:SFT 只会模仿示范;好示范贵且有限;模型学不会"多个都对里挑更好" —— **SFT 教"该怎么说",RLHF 教"怎么说得更好"** **一句话版三兄弟(已背)**: | | 打分者 | 基线 | 模型数 | 特点 | |---|---|---|---|---| | PPO | RM | Critic 预估 | 4 | 上限高,工程复杂 | | DPO | 无(偏好对) | Reference | 2 | 最简稳,像 SFT | | GRPO | RM/规则奖励 | 组内平均 | 3 | 省 Critic,DeepSeek/R1 用 | 记忆:GRPO = "别问 Critic,看看你兄弟们考多少分"。 --- ## Q6 幻觉 ⚠️(概念混,重点复习) **题目**:幻觉怎么产生的?至少 4 条缓解手段? **我的答案**:注意力稀释(错);温度 0 / 并行汇总 / 提示词常驻 / subagent 防污染。 **点评**:**幻觉 ≠ 注意力稀释**(lost in the middle 是长上下文退化,另一回事)。标准原因: 1. next-token 概率模型,目标是"像"不是"真" 2. 没有"我不知道"机制,SFT 教出了有问必答 3. 训练数据过时/噪声/长尾不足 4. (可加)上下文错/检索错,模型信以为真 我答的手法判定:温度 0 ⚠️(只消随机性,贪心照样编错);并行汇总 ✅(学名 **self-consistency**);提示词常驻 ❌(太含糊);subagent ⚠️(工程技巧非标准答案)。 **必背四条手段**:① RAG(主流,百度语境必提)② Prompt:允许说不知道 + 仅据给定资料 + 要求引用来源 ③ 事后校验(另一模型做 faithfulness 检查)④ 对齐(RLHF 校准拒答)。 套路:**原因"机制+数据+知识边界",手段"RAG/prompt/校验/采样"**。 --- ## Q7 死循环 ✅ **题目**:Agent 反复调同一工具同参数,为什么?怎么解? **我的答案**:①忘记目标→提示词常驻 ②结果没回传→把错误解析回传 ③幻觉偶发→设上限。 **点评**:三条都在点子上。②最准 —— 真实生产最常见原因。**核心句:"模型永远只能基于它看到的上下文决策,它看不到的东西等于没发生。"** 精修:① 长对话丢目标 → 重注入系统提示+任务 / 上下文压缩(联动 Q9/Q10 强项);③ 重复模式 → 重复检测。 **三道防线(背)**:轮次上限(max iterations,如 25 轮)/ 重复检测(同工具同参 N 次→终止或提醒)/ 明确终止条件+优雅降级。 高分原因:+**任务无解/工具能力不足**(查不到就无限换说法重试)→ 识别后主动终止告知用户。 --- ## Q8 Agent 评估 ✅✅(上次空白,本次突破) **题目**:怎么评测 Agent 效果?怎么设计评估体系? **我的答案**(按三层框架):评结果/过程/成本;规则自动+模型判+人工兜底;离线最好(在线影响系统)。 **点评**:框架全填上,过程评估是亮点。术语包装: - 评什么:任务成功率 / 过程评估(trajectory:工具选对没、参数对没、路径冗余没)/ 效率 / **安全**(漏了,补) - 怎么评:规则/代码评测(可验证任务,如代码跑用例)/ **LLM-as-a-judge**(rubric 打分;坑:位置偏差、长度偏差)/ 人工(建金标+校准 judge;评测集随 badcase 持续迭代 ✅ 已有此意识) - 何时评:**离线/在线不是二选一** —— 离线 = 改 prompt 后跑评测集回归(相当于 Agent 的单元测试);在线 = A/B、用户反馈、成功率监控(评测集和真实分布有 gap) **背诵版 20 字**:"评什么(结果/过程/效率/安全)→ 怎么评(规则+judge+人工)→ 何时评(离线回归+在线 AB)"。 --- ## Q9 开放设计:搜索深度研究 Agent ✅✅(高光) **题目**:设计"深度研究"功能:复杂问题 → 多轮搜索、读多网页、综合回答。 **我的答案**:agent loop + 搜索工具;重点难题①编排:主 agent 把 subagent 注册为工具,按公司拆三个并行搜索最后汇总;②"信息够了没":给 subagent 必要维度清单,收齐即停。 **点评**:独立复现了 Anthropic orchestrator-workers 多智能体研究系统;"维度收齐即停"= sufficiency rubric,是真解法。两漏洞: - **没提 citation**:subagent 返回必须带来源 URL+片段,综合挂引用 —— 搜索产品的幻觉防线 - **没提成本**:并行 subagent token 约 15 倍;要预算控制+问题难度路由(简单问题单 agent) - 高光机会:subagent 读网页后**压缩成要点再返回**(不塞原始页面)—— 联动我的记忆压缩强项,主动说 --- # 总体战报 | 部分 | 表现 | 备注 | |---|---|---| | Agent vs Workflow | ✅ | 表达排序待练 | | Function Calling | ✅ | 核心扎实,schema 细节补全 | | RAG 流程 | ✅ | chunking 策略待补 | | 多路召回/重排 | ⚠️ | HyDE 概念混;bi/cross-encoder 必背 | | RLHF 三兄弟 | ✅ | 一句话版已给已背 | | 幻觉 | ⚠️ | 机制解释错位;四条手段必背 | | 死循环 | ✅ | 结果回传抓得准 | | 评估 | ✅✅ | 上次空白→本次全填,质变 | | 开放设计 | ✅✅ | 独立想出 orchestrator-workers | **规律总结**:动手学过的扎实(loop/工具/记忆/评估实操感),纯听来的概念(HyDE、幻觉机制)易混。**最大短板仍是术语精确性**。 ## 新待办(9/2 更新) - [x] ~~背 Q15 评估框架~~(9/2 已能三层全填,差术语包装)→ 剩:背 "20 字背诵版" + LLM-as-a-judge 的两个偏差 - [ ] **bi-encoder vs cross-encoder 对比**(今天最大的坑,必背) - [ ] **幻觉:标准原因 3 条 + 缓解 4 条** - [ ] **多路召回三概念分清**:query 改写 / HyDE / 多通道 - [ ] 死循环三道防线 + "看不到=没发生"金句 - [ ] workflow 五模式名字 - [ ] PPO/DPO/GRPO 一句话版(今天已讲,复习一遍) - [ ] 开放设计答题模板:架构 + citation + 成本路由 + subagent 压缩返回 - [ ] (延续)读 Anthropic《Building effective agents》《How we built our multi-agent research system》 - [ ] (延续)过 Q14 归因表 - [ ] **简历要尽快做** —— 本次项目部分跳过,真实面试必有项目深挖
